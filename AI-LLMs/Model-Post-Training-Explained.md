# 模型后训练：怎样把示范和反馈变成能力

文件归档助手已经读到了正确规则，却总是在工具参数里写错日期，或者复制完几份文件就提前结束。这时，除了修改提示词和工具，也可以通过训练改变模型的行为倾向。

[《深入理解 AI Agent》第八章](https://github.com/bojieli/ai-agent-book/blob/main/book/chapter8.md)围绕模型参数更新展开。本篇承接[评估导读](Agent-Evaluation-Explained.md)，用文件归档任务解释训练方法：先分清缺什么能力，再看什么数据能教会它，最后检验训练有没有改善新任务。例子均为教学假设。

**训练改变的是模型产生答案的概率。**

模型参数，也称权重，是神经网络内部参与计算的数值。给定上下文，模型为下一个 token 分配概率；token 是文本等内容被编码后的处理单位，不一定对应一个汉字或单词。连续选择 token，就构成回答或工具调用。

训练通过损失函数衡量预测与目标的差距。梯度描述参数变化会怎样影响损失，优化器据此小幅调整参数。学习率控制每次调整的尺度：过大可能不稳定，过小则学习缓慢。正常推理只使用已有参数，不会因为用户纠正一句话就自动完成这套更新。

例如，训练前模型遇到同名文件，经常直接覆盖；训练后，在适当条件下，它更可能选择检查内容或生成不同文件名。要确认它学会了这个判断，应测试新的目录和文件，而非只重复训练中的例子。

**四个训练环节，分别提供不同的学习材料。**

| 环节 | 主要材料 | 在归档助手中的作用 |
| --- | --- | --- |
| 预训练（Pre-training） | 大量文本、代码等数据 | 建立语言、文件操作和代码等通用基础 |
| 中期训练（Mid-training） | 目标领域的文档、代码和能力语料 | 加深对专用文档结构、术语和关联的理解 |
| 监督微调（SFT） | 输入与期望输出的示范 | 学习日期格式、工具协议和操作流程 |
| 强化学习（RL） | 自己执行任务的轨迹及奖励 | 提高能正确完成任务的策略出现的概率 |

这些是常见环节，不是每个项目必须依次完成的清单。中期训练常采用继续预测下一个 token 的目标；领域自适应预训练就是其中一种做法。[Don't Stop Pretraining](https://arxiv.org/abs/2004.10964)研究了继续在领域及任务数据上训练的效果。

若只缺“这个月新增了什么归档规定”，通常可以先检索最新文档。RAG（检索增强生成）是在回答前寻找资料并放入上下文，适合需要更新和引用的事实。若模型拿到资料仍长期看不懂某种专业语言，才更有理由考虑补充领域训练。

**SFT 教模型模仿可接受的行为。**

SFT 是 Supervised Fine-Tuning，监督微调。例如给出一组示范：“用户请求、目录信息 → 正确的工具调用”，让模型提高示范输出的概率。常见做法只对回答部分计算损失，把用户输入和工具返回当作条件；这叫损失屏蔽（Loss Masking）。具体屏蔽哪些部分取决于训练目标。

示范不能只包含顺利归档。还需要有同名文件、缺失日期和操作失败的情况，展示何时查询、何时报告问题、何时可以完成。否则模型可能只学会表面顺序。训练集上表现很好、新场景上失效，称为过拟合；对未见过的任务仍然有效，才是泛化。

LoRA（低秩适配）解决的是训练开销：冻结原有权重，训练较小的附加矩阵，以较少可训练参数表示权重的改变量。它可用于多种微调目标，并不限定为 SFT，也不保证旧能力完全不受影响。[LoRA 论文](https://arxiv.org/abs/2106.09685)

**RL 让模型通过执行结果调整策略。**

强化学习中的策略，是在当前条件下选择行动的概率规则。环境包含模型交互的文件、工具和外部状态；一次从初始状态执行到结束的过程称为 episode，采样得到的过程记录常称为 rollout。

在归档环境中，可以让模型实际查询、筛选、复制，再由验证器检查文件是否齐全、内容是否一致。验证结果形成奖励。训练反复进行“采样轨迹 → 评分 → 更新策略”，逐渐增加高奖励行为的概率。

困难在于信用分配：如果十步以后才发现归档遗漏，究竟是哪一步导致失败？价值函数估计从当前状态继续执行能获得多少回报；优势（Advantage）衡量某次选择比基准预期好多少。它们帮助训练程序利用延迟出现的反馈。

经典 Q-learning 学习“状态下采取某个动作的长期价值”。其背后的贝尔曼关系把长期价值拆成即时奖励与后续价值。语言模型的行动由变长 token 序列组成，常采用直接优化行动概率的策略梯度方法，而不是为所有可能回答建立一张价值表。

PPO（近端策略优化）在采样后优化一个替代目标，通过裁剪等机制抑制过大的更新，常配合价值模型估计优势。裁剪不是“每次更新一定安全”的硬保证。[PPO 论文](https://arxiv.org/abs/1707.06347)

GRPO（组相对策略优化）则让同一道题的多条结果互相比较，用组内奖励计算相对优势，省去单独训练价值模型的开销。如果整组都失败、奖励相同，就缺少有用的组内区分信号。[DeepSeekMath](https://arxiv.org/abs/2402.03300)

因此，反复试错需要能获得反馈。若模型连工具格式都不会，可以先给示范；若任务太难，可以从更简单且相关的任务开始，这叫课程学习。增加采样量有时能找到成功路径，但不能保证解决基础能力缺口。

**奖励要反映结果，也要反映必要的约束。**

如果奖励只看归档目录有多少文件，模型可能复制无关文件；如果只惩罚操作次数，它可能提早结束。奖励作弊（Reward Hacking）就是策略利用评分漏洞获取高分，却没有实现实际目标。

结果奖励在任务末尾检查是否完成，允许模型探索不同路径；过程奖励评价中间步骤，反馈更密集，但错误的过程标准可能把模型锁定在低效流程中。可以逐维度记录完成度、重复操作和越界行为，再按任务要求决定哪些加权、哪些直接否决。

RLVR 是使用可验证奖励的强化学习，例如通过独立文件检查评分。RLHF 是从人类反馈中学习，经典流程先用偏好数据训练奖励模型，再优化策略。生成式奖励模型还会输出解释，但解释清楚不代表评分必然正确。

DPO（直接偏好优化）从“同一输入下更好与更差的输出”成对数据中学习，不需要在标准训练流程中另训显式奖励模型、持续采样环境轨迹。例如把“未检查就说完成”与“先核对清单再报告”组成偏好对。[DPO 论文](https://arxiv.org/abs/2305.18290)

**蒸馏让教师提供更密集的指导。**

蒸馏是让学生模型学习教师的输出或预测分布。教师可以先在完整提示下产生经验证的示范，再训练学生用更短的输入完成同类任务；也可以提供公开、可用的推导示范，让学生学习中间步骤。省掉多少提示或计算，需要实测，不能假定能力会无损转移。

离轨蒸馏主要学习教师走过的路径；在轨蒸馏（On-Policy Distillation）让学生先走出自己的路径，再请教师在学生实际遇到的状态上提供逐 token 指导。学生把文件选错以后，教师能针对这个错误状态指导恢复，比只看最终失败分数更具体。[Thinking Machines Lab 的在轨蒸馏说明](https://thinkingmachines.ai/blog/on-policy-distillation/)

这里“在轨”指数据来自当前策略或足够接近的策略。“在线”仅表示训练过程中持续产生数据；如果生成数据的模型版本落后，数据仍可能离轨。大规模训练还要核对采样端与训练端的数值计算，权重相同不代表实现差异可以忽略。

自蒸馏可让同一个模型承担两种角色：教师额外看到已验证答案，学生只看题目。额外信息才是指导来源，不能在正式测试时泄露给学生。比较预测分布时常用 KL 散度，它衡量两个概率分布的差异，并不是对称的距离。

**把训练接回评估，才知道学到了什么。**

假设我们要纠正“尚未完成就收尾”。训练数据需要包含这种失败，也需要保留已经完成、应该正常结束的例子。只惩罚结束，可能训练出反复检查、迟迟不交付的新问题。

将触发问题的任务用于构造训练材料，再用独立的新任务验证迁移，用旧任务检查能力保留。灾难性遗忘指新训练明显破坏原有能力，可以通过混入旧任务数据、控制更新幅度等方式缓解，但最终仍需测试。SFT 和 RL 都可能泛化，也都可能过拟合；方法名本身不决定结果。

对归档助手，可以从一个具体错误开始：缺资料先补资料，格式不稳定先考虑示范，策略选择不佳且有可靠奖励再考虑 RL。若教师能在学生错误现场给出有效指导，则可以比较蒸馏的成本收益。这样训练方案始终对应可验证的能力缺口。
