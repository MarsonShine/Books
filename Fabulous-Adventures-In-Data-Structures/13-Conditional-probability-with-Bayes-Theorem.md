## 贝叶斯定理

18世纪的英国统计学家托马斯·贝叶斯未能亲眼见证他在概率论方面的工作得以发表，但在现代，它已成为我们最重要的统计工具之一。这是因为贝叶斯定理使我们能够逆向推理：通过观察结果产生的证据，我们可以更新对原因的看法。让我们看一个简单的例子，了解它是如何工作的。假设我们戴上频率学派的帽子，对10000人进行一项科学调查，询问两个问题。第一，你现在感冒了吗？第二，你在过去24小时内打喷嚏了吗？我们可以将结果整理成一张边缘表：

表13.1 对10000名受访者的调查结果按边缘表组织；边缘上的合计行和合计列非常有用。

​                            感冒：是    感冒：否    合计

打喷嚏：是       860        270     1130
打喷嚏：否       140       8730     8870
合计                    1000       9000    10000

这被称为边缘表，因为有趣的信息来自表格边缘的“合计”行和列。让我们重新戴上贝叶斯学派的帽子，并根据这张表的证据，思考一些随机路人的问题：

- 如果我们除了这些数据之外没有其他观测结果，随机在街上选一个人，我们有多大把握认为他们感冒了？换句话说，感冒在人群中的患病率是多少？最下面一行显示，每10000人中约有1000人感冒，因此我们认为随机一个人感冒的概率大约是10%。我们将“概率”缩写为“P”，“感冒”缩写为“C”，并用P(C)表示随机一个人感冒的概率。这就是先验概率：在我们了解关于此人的更多事实之前，认为随机一个人感冒的信念强度。
- 再随机选一个路人，问他们是否感冒；他们回答“是”。基于这一证据，我们有多大把握认为他们在过去24小时内打过喷嚏？最左边一列告诉我们，1000名感冒患者中有860人打过喷嚏，因此我们应该有高达86%的把握认为这个人打过喷嚏。传统的记法有些不幸：我们说在已知感冒的证据下打喷嚏的条件概率是P(S|C)。竖线表示“如果”，意思是“如果此人感冒，那么他打过喷嚏的概率”。
- 再随机选一个人：我们有多大把握认为他们既感冒又最近打过喷嚏？这可以从表格的左上角和右下角推导出来：有860人符合这个描述，总共有10000人，因此我们的把握只有8.6%。我们将联合概率记作P(C&S)。

> **注意** 不幸的是，我们在概率记法和许多编程语言中都使用“&”表示“和”，但在这里我们用“|”表示“如果”，而不是“或”。在本章中，竖线始终表示“如果”。

你可能已经注意到10% × 86% = 8.6%，这并非巧合。通常有：
$P(C) × P(S|C) = P(C\&S)$
这是有道理的：C和S同时发生的联合概率等于C发生的先验概率乘以在C发生条件下S发生的条件概率。我们还可以从边缘数据中推导出另外两个事实：

- 我们认为一个随机路人在过去一天内打过喷嚏的概率是多少？最右边一列告诉我们，10000人中有1130人在前一天打过喷嚏。所以P(S) = 11.3%。


- 再随机选一个路人，问他们最近是否打过喷嚏；他们回答“是”。我们有多大把握认为他们感冒了？最上面一行告诉我们，1130名打喷嚏的人中有860人确实感冒了，所以P(C|S) = 860/1130 ≈ 76.1%。


这里稍微难看出来，因为数字不是整数，但确实11.3% × 76.1% = 8.6%。不出所料，一个人既感冒又打喷嚏的概率等于他们打喷嚏的概率乘以在打喷嚏条件下他们感冒的概率。
$P(S) × P(C|S) = P(C\&S)$
这两个等式的右边相等，因此左边必然相等。我们可以将这两个等式结合起来推导出贝叶斯定理。对于任意C和S，先验概率和条件概率之间具有如下优美的对称关系：
$P(S) P(C|S) = P(C) P(S|C)$

贝叶斯定理的强大之处在于它能精确计算我们在基于证据的诊断中的置信度。随机选一个人；在什么也不问的情况下，你有多大把握认为他们感冒了？除了调查结果之外一无所知时，P(C) = 10%；这是先验概率，因为它是我们在观察到额外证据之前的信念。现在如果我们问他们最近是否打过喷嚏，他们回答“是”，那么我们认为他们感冒的信念从P(C)=10%上升到P(C|S)≈76.1%，这是一个巨大的更新。这就是后验概率：观察到额外证据之后的信念强度。

这种对调查数据的分析捕捉了特定时间点、特定群体（10000人）中的事实，但感冒及其引发的打喷嚏具有季节性；我们应该预期P(C)和P(S)会随时间和调查人群而变化。如果我们能从边缘表中推导出不变的事实，那将大有帮助。

从第一列我们看到，仅就感冒人群而言，860/1000 = 86%的人最近打过喷嚏；这就是条件概率P(S|C)。从第二列我们看到，没有感冒的人群中有270/9000 = 3%的人最近打过喷嚏——这就是条件概率P(S| not C)。我们可以假设感冒会导致打喷嚏，因此打喷嚏的似然是是否感冒的函数。我们还可以进一步假设似然函数不会随时间变化，即使感冒的先验概率会随季节变化。这是一个非常简单的疾病统计模型。

现在我们已经掌握了贝叶斯定理的基本数学和术语，可以继续编写一些代码了。

## 似然函数与联合分布

> 似然函数：
>
> **似然函数就是一个"if-then"的规则**。在上面感冒的例子里：
>
> - 如果一个人**感冒了**，他打喷嚏的概率是 **86%**
> - 如果一个人**没感冒**，他打喷嚏的概率是 **3%**
>
> 那么就有似然函数：
>
> ```
> sneezed.ToCategorical(14, 86);   // 如果感冒：14% 不打喷嚏，86% 打喷嚏
> sneezed.ToCategorical(97, 3);    // 如果不感冒：97% 不打喷嚏，3% 打喷嚏
> ```
>
> 联合分布：
>
> **联合分布就是两件事同时发生的概率**。上面表格的每个格子就是一个联合事件：
>
> - (感冒，打喷嚏) = 860人
> - (感冒，没打喷嚏) = 140人
> - (没感冒，打喷嚏) = 270人
> - (没感冒，没打喷嚏) = 8730人
>
> **联合分布就是用数学方式表示这个表格**。

我们要做的第一件事是将似然函数转换为代码。首先用类型表示我们的两种状况：

```csharp
enum Cold { No, Yes }
enum Sneezed { No, Yes }
```

清单13.1 实现了一个函数，该函数接受一个人是否感冒，并返回一个打喷嚏的分布：当传入 `Cold.Yes` 时返回 86%（即 P(S|C)）的分布；当传入 `Cold.No` 时返回 3%（即 P(S|¬C)）的分布：

清单13.1 将打喷嚏与感冒联系起来的似然函数

```csharp
static IDiscreteDistribution<Sneezed> SneezedGivenCold(Cold c)
{
    List<Sneezed> sneezed = [Sneezed.No, Sneezed.Yes];
    return c == Cold.No ?
        sneezed.ToCategorical(97, 3) :
        sneezed.ToCategorical(14, 86);   #A
}
#A 我们自动将其化简为 7 和 43
```

这是一个重要的见解：条件概率的分布可以表示为似然函数，该函数接受一个条件（某个人是否感冒？）并返回概率分布（我们有多大把握认为这个人最近打过喷嚏？）。

仅凭这一点，我们已经可以做很多事情。例如，我们可以模拟另一项调查。我们将生成 10000 个人，随机分配其中 10% 的人感冒，然后根据似然函数随机分配他们最近是否打喷嚏，从而生成一个包含 10000 个 (Cold, Sneezed) 元组的序列。通过同时采样两个（或更多）随机量来生成元组的概率分布称为联合分布。如果一切正常，它应该与表13.1中的数据相似：

```csharp
List<Cold> cold = [Cold.No, Cold.Yes];
var prior = cold.ToCategorical(90, 10);
var cs = prior.Samples().Take(10000)
    .Select(c => (c, SneezedGivenCold(c).Sample()));
Console.WriteLine(cs.Histogram());
```

果然，这个随机生成的模拟调查的直方图与原始调查非常相似：

```
(No, No)| 8758|****************************************
(No, Yes)|  288|*
(Yes, No)|  137|
(Yes, Yes)|  817|***
```

然后我们可以模拟其他场景：假设 20% 的人口患有感冒。如果我们将先验改为 (80, 20) 分布并重新运行上述代码，我们将从一个不同的联合分布中获取样本，该联合分布中感冒总数是原来的两倍，打喷嚏数也相应增加：

```
(No, No)| 7802|****************************************
(No, Yes)|  252|*
(Yes, No)|  279|*
(Yes, Yes)| 1667|********
```

给定一个先验和一个似然函数，我们已经看到我们可以从生成的联合分布中生成样本；如果能精确地用一个对象来表示该联合分布，那将非常棒。这是一个类别分布，其中类别是元组，并且我们拥有计算联合分布支撑集中四个元组值各自权重的所有必要信息。

如果所有权重都是介于 0 和 1 之间的分数，那么确定联合分布表中每个条目的概率就很直接。让我们来做一个例子；我们可以先重申先验概率和似然概率：

- P(C) = 0.1
- P(¬C) = 0.9
- P(S|C) = 0.86
- P(¬S|C) = 0.14
- P(S|¬C) = 0.03
- P(¬S|¬C) = 0.97

四个联合概率可以通过相乘得到：

- P(C & S) = P(C) P(S|C) = 0.086
- P(C & ¬S) = P(C) P(¬S|C) = 0.014
- P(¬C & S) = P(¬C) P(S|¬C) = 0.027
- P(¬C & ¬S) = P(¬C) P(¬S|¬C) = 0.873

它们加起来等于 1.0，乘以 10000 后与表13.1中的观测数据匹配，所以目前看来一切正确。不幸的是，我在上一章中为了简化别名方法的实现而决定使用整数权重，现在反过来困扰着我。我们该如何用整数进行同样的计算以获得非归一化的权重呢？假设我们试图计算 (Cold.Yes, Sneezed.Yes) 的权重。Cold.Yes 的先验权重是 1，总分布权重为 10。在给定 Cold.Yes 的条件下，Sneezed.Yes 的条件似然权重是 43，总权重为 50。但是 1 乘以 43 再除以 50 会得到一个分数，而不是整数。

我们可以通过先编写几个辅助函数来解决这个问题。我们需要一个分布的总权重、两个数的最小公倍数（LCM），以及任意多个数的最小公倍数；即能够被所有这些数整除的最小整数。幸运的是，我们已经有了所需的内容；在第12章中我们实现了一个计算最大公约数（GCD）的函数，由此我们可以计算 LCM：

清单13.2 从 GCD 计算 LCM

```csharp
public static class Extensions
{
    [...]
    public static int LCM(this int x, int y) =>
        x * y / x.GCD(y);
    
    public static int LCM(this IEnumerable<int> numbers) =>
        numbers.Aggregate(1, LCM);
    
    public static int TotalWeight<T>(
        this IDiscreteDistribution<T> distribution) =>
        distribution.Support().Select(s => distribution.Weight(s)).Sum();
}
```

如果我们取每个条件分布的总权重的 LCM，那么该 LCM 将始终能被其中任何一个总权重整除。我们可以将先验权重乘以这个 LCM 作为一个常数因子，以确保后续除以总权重时结果总是整数。下面是如何在给定先验和似然函数的情况下计算联合分布：

清单13.3 从先验和似然函数计算联合分布

```csharp
public static class Extensions
{
    [...]
    public static IDiscreteDistribution<(A, B)> ToJoint<A, B>(
        this IDiscreteDistribution<A> prior,
        Func<A, IDiscreteDistribution<B>> likelihood)
    {
        int lcm = prior.Support()
            .Select(a => likelihood(a).TotalWeight())
            .LCM();                                      #A
        List<(A, B)> jointSupport = [];
        List<int> jointWeight = [];
        foreach (A a in prior.Support())
        {
            var db = likelihood(a);
            foreach (B b in db.Support())
            {
                jointSupport.Add((a, b));
                jointWeight.Add(
                    prior.Weight(a) * db.Weight(b) * lcm /
                    db.TotalWeight());
            }
        }
        return jointSupport.ToCategorical(jointWeight);
    }
}
#A 使用总权重的 LCM 作为常数因子
```

如果我们所做的一切正确，我们应该能够从先验和似然函数中得到一个 (Cold, Sneezed) 元组的联合分布，该分布与表13.1中原始调查数据的比例相匹配：

```csharp
var prior = cold.ToCategorical(90, 10);
Console.WriteLine(prior.ToJoint(SneezedGivenCold).ShowWeights());
```

果然，我们得到了精确的结果：

```
(No, No):873
(No, Yes):27
(Yes, No):14
(Yes, Yes):86
```

然后，如果我们将先验改为三倍数量的感冒患者，我们可以从相同的似然函数自动计算出新的联合分布：

```csharp
var prior = cold.ToCategorical(70, 30);
Console.WriteLine(prior.ToJoint(SneezedGivenCold).ShowWeights());
```

我们的模型预测感冒和打喷嚏的比例将如下所示：

```
(No, No):679
(No, Yes):21
(Yes, No):42
(Yes, Yes):258
```

到目前为止的故事总结如下：

- 作为频率学派，我们可以收集真实世界的数据观测，形成假设来构建统计模型。我们可能假设患有感冒会导致一天内打喷嚏的似然从无感冒时的约3%上升到有感冒时的约86%，并且这种似然随时间变化不大。这个模型可以在代码中表示为一个返回概率分布的似然函数。
- 我们可以将该似然函数应用于任何先验（即随机一个人当前感冒的概率），以生成一个联合概率分布。
- 我们还没有解锁贝叶斯推理的全部威力。似然函数使我们能够从诊断（“此人感冒了”）出发，预测他们的症状（“他们有86%的可能性最近打过喷嚏”）。
- 贝叶斯定理的对称性允许我们反向操作。给定一个症状的观测（“此人最近打过喷嚏”），我们希望对诊断的准确性进行估计（“他们感冒的可能性有多大？”）。接下来我们就来做这个。

> 如何从似然函数推导出联合分布？
>
> **给定两个信息：**1.**先验概率**：10%的人感冒（P(C) = 0.1）。2.**似然函数**：感冒的人86%会打喷嚏
>
> **可以计算所有四个格子！**
>
> **格子1：(感冒，打喷嚏)**
>
> - 先验：10%的人感冒
> - 条件概率：这10%的人中86%会打喷嚏
> - 结果：10% × 86% = 8.6%
>
> **格子2：(感冒，不打喷嚏)**
>
> - 先验：10%的人感冒
> - 条件概率：这10%的人中14%不会打喷嚏
> - 结果：10% × 14% = 1.4%
>
> **格子3：(不感冒，打喷嚏)**
>
> - 先验：90%的人不感冒
> - 条件概率：这90%的人中3%会打喷嚏
> - 结果：90% × 3% = 2.7%
>
> **格子4：(不感冒，不打喷嚏)**
>
> - 先验：90%的人不感冒
> - 条件概率：这90%的人中97%不会打喷嚏
> - 结果：90% × 97% = 87.3%
>
> 验证：8.6% + 1.4% + 2.7% + 87.3% = 100% ✓

## 通过从结果逆向推理到原因来更新先验

当观察到新证据时，我们应该更新自己的信念。如果我们的先验信念是“目前有10%的人感冒了”，而某人提供了他们最近打过喷嚏的证据，那么他们感冒的后验概率是多少？这就是诊断的本质：观察结果，然后逆向推理到原因。

在本章早些时候，我们从表13.1中推导出了后验概率；我们注意到，如果我们将注意力集中在边缘表中，只检查最近打过喷嚏的1130人，其中860人有感冒，因此对于打过喷嚏的人，我们应当有860/1130的把握认为他们感冒了。

在上一节中我们刚刚学到，在给定先验和似然函数的情况下，我们可以计算联合概率分布；该联合概率分布的权重比例与我们用来假设似然函数的边缘表相同。因此，我们可以通过对联合分布施加一个过滤器，丢弃与新证据不一致的可能性，来计算后验似然函数：

清单13.4 计算后验似然函数

```csharp
static class Extensions
{
    [...]
    public static Func<B, IDiscreteDistribution<A>> Posterior<A, B>(
        this IDiscreteDistribution<A> prior,
        Func<A, IDiscreteDistribution<B>> likelihood) =>
        b => prior.ToJoint(likelihood)                     #A
            .Filter(joint =>                               #B
                EqualityComparer<B>.Default.Equals(joint.Item2, b))   #C
            .Project(joint => joint.Item1);                #D
}
#A 生成 (A, B) 对的联合分布
#B 过滤掉除匹配 b 之外的所有行
#C C# 没有提供泛型等号运算符，但提供了一个辅助方法
#D 得到 A 的结果分布
```

将此代码的行为与改写为求解 P(A|B) 的贝叶斯定理进行比较：

$P(A|B) = P(A) P(B|A) / P(B) = P(A\&B) / P(B)$

在该定理中：

- P(A) 是 A 的先验概率；*先验：感冒的概率*
- P(B|A) 是在给定 A 条件下 B 的条件概率；*似然：给定感冒，打喷嚏的概率*
- 它们的乘积是联合概率 P(A&B)；*联合分布：既感冒又打喷嚏*
- 后验概率 P(A|B) 是 P(A&B) 除以 P(B)；*后验：给定打喷嚏，感冒的概率*

每个部分在我们的代码中都有精确的对应：

- 一个 `IDiscreteDistribution<A>` 类似于先验 P(A)
- 一个类型为 `Func<A, IDiscreteDistribution<B>>` 的函数类似于条件概率 P(B|A)
- 由 `ToJoint` 返回的类型为 `IDiscreteDistribution<(A,B)>` 的联合分布类似于联合概率 P(A&B)
- 调用 `Filter` 和 `Project` 从联合分布中丢弃无关数据类似于将 P(A&B) 除以 P(B)
- 返回的类型为 `Func<B, IDiscreteDistribution<A>>` 的函数类似于后验概率 P(A|B)

让我们试一下。给定先验（10% 的人感冒）以及表示疾病模型的似然函数，打过喷嚏的人患有感冒的后验概率分布是什么？

我们手动推算得出，对于打过喷嚏的人，应当有 860/1130 的把握认为他们感冒，270/1130 的把握认为他们没有感冒。事实上，我们得到的权重比例恰好是 860 比 270，化简为 86 比 27：

```csharp
var prior = cold.ToCategorical(90, 10); // 10%的人感冒
var posterior = prior.Posterior(SneezedGivenCold);
Console.WriteLine(posterior(Sneezed.Yes).ShowWeights());
```

输出结果：

```
(No):27
(Yes):86
```

此时你可能会想，当然，我们比调用 Random 掷骰子有了很大的改进；我们现在可以用整数权重表示任何有限离散分布，用似然函数表示条件概率，等等。但这个工具到底有多强大？最近打过喷嚏的人比没打过喷嚏的人更可能感冒——这就是我们学到的全部吗？

软件开发人员需要更好的贝叶斯推理工具，因为它可能违反直觉，而弄错的后果可能非常严重。接下来，我们将应用目前构建的工具来回答一个关于医学检测的真实问题，然后思考如何将这些工具用于其他应用。

## 贝叶斯推理的一些应用

有一种我刚刚编造出来的罕见疾病，叫做弗罗布综合征；每 30000 人中约有 1 人患有这种虚构的疾病。我有一种昂贵且 100% 准确的“金标准”检测方法用于弗罗布综合征。我们不可能对每个人都用昂贵的检测方法进行合理检测。

幸运的是，医学研究的公共资助带来了一种相对便宜的血液检测方法。对比两种检测方法的严谨试验表明，廉价检测方法的准确率为 99.5%，仅比昂贵检测方法差 0.5%。你决定做这个廉价检测。果然，廉价检测结果显示你为弗罗布综合征阳性。在不进行数学计算的情况下，仅凭直觉，基于这一证据，你认为自己患有弗罗布综合征的信念强度是多少？

很多人会说，如果检测准确率是 99.5%，且检测结果为阳性，那么你的信念强度也应该是 99.5%。但作为一个有原则的贝叶斯主义者，你应该立即对任何在不提及先验的情况下就给出后验的推理产生怀疑。让我们编写代码，看看我们的概率工具库会给出什么结果。我们可以从两种表示结果的类型开始：

```csharp
enum Frob { No, Yes }
enum CheapTest { Negative, Positive }
```

先验是：30000 人中有 1 人患有弗罗布综合征，29999 人没有：

```csharp
List<Frob> frob = [Frob.No, Frob.Yes];
var frobPrior = frob.ToCategorical(29999, 1);
```

似然函数将廉价检测的结果与是否存在该综合征联系起来。如果你没有患弗罗布综合征，那么每 1000 次中有 995 次检测结果为阴性。如果你确实患有该综合征，那么每 1000 次中有 995 次检测结果为阳性：

```csharp
static IDiscreteDistribution<CheapTest> TestResultGivenFrob(Frob f)
{
    List<CheapTest> cheap = [CheapTest.Negative, CheapTest.Positive];
    return f == Frob.No ?
        cheap.ToCategorical(995, 5) :
        cheap.ToCategorical(5, 995);
}
```

注意 医学检测在阳性人群中的准确度称为检测灵敏度，在阴性人群中的准确度称为检测特异度。我假设廉价检测的灵敏度和特异度均为 99.5%；实际上，许多检测的灵敏度和特异度差异很大，正如我们之前用打喷嚏作为感冒检测指标的例子所示。

现在我们可以得到后验似然函数，它将回答我们的问题：在检测结果为阳性的情况下，真正患有该综合征的分布是什么？

```csharp
var frobPosterior = frobPrior.Posterior(TestResultGivenFrob);
Console.WriteLine(frobPosterior(CheapTest.Positive).ShowWeights());
```

在检测呈阳性之后，你实际应该持有的信念强度是：

```
No:29999
Yes:199
```

在检测准确率为 99.5% 且结果为阳性的情况下，你患有弗罗布综合征的几率仅为 199 比 29999！也就是 0.7%。你很可能仍然没有患弗罗布综合征。这怎么可能呢？联合分布说明了问题：

```csharp
Console.WriteLine(frobPrior.ToJoint(TestResultGivenFrob).ShowWeights());
```

得到的联合分布如下：

```
(No, Negative):5969801
(No, Positive):29999
(Yes, Negative):1
(Yes, Positive):199
```

频率学派会说，如果我们用廉价检测方法检测 600 万随机人群，其中大约 200 人确实患有弗罗布综合征。在这 200 名阳性患者中，有 1 人（200 的 0.5%）得到假阴性检测结果，199 人得到真阳性检测结果。但在近 600 万实际为阴性的人群中，每 200 人中就有 1 人得到假阳性检测结果，导致 29999 例假阳性，远远超过真阳性数量。

贝叶斯学派会说，你在检测前认为自己患有弗罗布综合征的信念强度是 1/30000，而你认为检测出错的信念强度是 1/200，后者要大得多。在观察到一份大约每 200 次就会出错一次的检测证据之后，你的后验（检测后）信念应该大约是先验信念的 200 倍，但 200 乘以 1/30000 仍然是一个很小的数。

如果你的检测结果为阳性，你很可能并没有患弗罗布综合征。相反，如果你的检测结果为阴性，你几乎不可能患有弗罗布综合征，因为你必须同时是 600 万人中那 200 名不幸患者之一，并且还是那 200 人中唯一一个检测结果出错的人。

人们（包括程序员、数学家和医学专业人士）经常错误地理解这个推理，因为直觉上感到荒谬：你在一个准确率为 99.5% 的检测中得到阳性结果，却仍然只有 0.7% 的几率真正患病，但事实就是如此。决定是否推荐这样的检测以及正确解读结果需要仔细关注数学原理，特别是当结果对医疗决策有影响时。

当然，贝叶斯推理还有许多适用于计算机程序员的非医学应用。作为开发者，我们经常拥有足够的数据来推导先验和似然函数，然后希望从中推导出后验函数，该函数告诉我们根据相关证据的观察，某件事发生的可能性有多大。

我们现在可以解决本书这一部分引言中提出的问题：从一个装有 999 枚正常硬币和一枚双面硬币的袋子中随机抽取一枚硬币。如果它连续十次抛出正面，那么你抽到双面硬币的概率是多少？

注意 这个问题是许多真实问题的抽象版本。例如：假设最近创建的社交媒体账户中每千个只有一个是真人，并且观察到十次符合真人行为的行为，那么该账户是真人的后验概率是多少？

我们可以快速编写代码来解决这个玩具版本的问题。从表示两种硬币类型和可能结果的类型开始：

```csharp
enum Coin { Normal, DoubleHeaded }
enum Flip { Tails, Heads }
```

似然函数给出了抛掷结果的可能分布：

```csharp
static IDiscreteDistribution<Flip> FlipGivenCoin(Coin c)
{
    List<Flip> flip = [Flip.Tails, Flip.Heads];
    return c == Coin.Normal ?
        flip.ToCategorical(1, 1) :
        Singleton<Flip>.Distribution(Flip.Heads);
}
```

现在我们可以计算在观察到连续十次正面之后持有双面硬币的后验分布。在查看下面的输出之前，如果你连续抛掷十次正面，你认为自己拥有双面硬币的信念强度是多少？

```csharp
List<Coin> coins = [Coin.Normal, Coin.DoubleHeaded];
var tenflips = coins.ToCategorical(999, 1)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads)
    .Posterior(FlipGivenCoin)(Flip.Heads);
Console.WriteLine(tenflips.ShowWeights());
```

后验的权重为：

```
Normal:999
DoubleHeaded:1024
```

如果你观察到连续十次正面，你持有双面硬币的可能性略高于 50%。一旦你习惯像贝叶斯主义者那样思考，这就会变得直观起来：如果你抽到的是正常硬币，连续抛掷十次正面的概率非常接近千分之一，但抽到双面硬币的概率恰好是千分之一。产生观察到的连续十次正面的唯二情景的可能性非常接近，因此后验概率应该在 50% 左右。

### 几个真实世界的例子

以下是几个与程序员相关的贝叶斯推理真实世界例子：

- 贝叶斯推理在互联网规模上的早期应用是自动删除垃圾邮件。我们可以手动将样本邮件分类为垃圾邮件和非垃圾邮件，从而获得垃圾邮件的先验。然后我们可以推导出一个似然函数，该函数提供在垃圾邮件和非垃圾邮件中可能出现的单词的分布。现在我们有了先验和似然函数，就可以自动生成我们真正需要的后验函数：给定一封新邮件中的单词，它是垃圾邮件的可能性有多大？

- 我在 Facebook 时，我的团队有一个贝叶斯模型，其中先验是不同品牌网络路由器的故障率，似然函数根据各种路由器故障类型生成不同丢包错误类型的分布。我们计算的后验函数是：在观察到数据中心中的丢包情况后，哪个路由器最可能是故障的那一个？

- 许多社交网络使用（通常报酬较低的）人工进行内容审核。给定不同类别不良内容（色情、诈骗、骚扰、医疗 misinformation 等）的先验分布，以及描述审核员在对帖子进行分类时所犯错误分布的似然函数，我们可以推导出一个后验：在观察到审核员之间对分类存在分歧的情况下，哪个审核员更可能是正确的？

- 工厂中的自动焊接机器有多个传感器用于检测零件何时停止移动，以便安全地进行焊接。给定零件在实际中正确停止频率的先验，以及传感器在零件停止和移动状态下的准确度似然，我们可以计算后验：在观察到传感器读数的情况下，零件确实安全停止的概率是多少？

- 开发者工具可以使用贝叶斯推理。给定代码库中函数调用名称分布的先验，以及开发者在意图调用某个函数时键入特定字母的似然，IDE 可以计算后验：在观察到一次按键后，开发者最可能尝试调用哪个函数？

在我们结束关于离散分布贝叶斯推理的讨论之前，我想简要介绍一个重要的特例。我们知道似然函数表示条件概率，但如果似然函数中没有任何条件呢？

## 无条件似然函数是独立的

我们已经看到如何将先验与似然函数结合起来生成一个联合分布，其中一个随机量的似然依赖于另一个随机量：打喷嚏的分布取决于一个人是否感冒，正面的分布取决于硬币是否是双面的，等等。

我们经常遇到这样的情况：有两个完全独立的随机事件，我们希望将它们组合起来。例如，在《龙与地下城》等桌面角色扮演游戏中，一种常见的游戏机制是“优势掷骰”：掷一个 20 面的“d20”骰子两次，然后舍弃较低的掷骰结果。第二次掷骰结果的分布并不依赖于第一次掷骰的结果。我们如何在一个分布中表示两个独立随机量的组合？我们可以使用相同的机制来组合先验和似然函数，但只需让似然函数变成无条件的即可。

一个 20 面的公平骰子近似于离散均匀分布；我们需要加 1，使支撑集变为整数 1 到 20，而不是 0 到 19：

```csharp
var d20 = DiscreteUniform.Distribution(20).Project(d => d + 1);
```

为了表示优势掷骰，我们生成两次 d20 掷骰的联合概率，得到 400 种可能的数对分布，然后对数值对施加投影以挑出较大的那个：

```csharp
var advantage = d20.ToJoint(_ => d20)
    .Project(pair => Math.Max(pair.Item1, pair.Item2));
Console.WriteLine(advantage.ShowWeights());
```

优势掷骰的权重如下：

```
1:1   2:3   3:5   4:7
5:9   6:11  7:13  8:15
9:17  10:19 11:21 12:23
13:25 14:27 15:29 16:31
17:33 18:35 19:37 20:39
```

正常掷骰时，掷出 20 的概率与掷出 1 的概率相同。而在优势掷骰中，你掷出 20 的可能性是掷出 1 的 39 倍！这是一个巨大的优势。

在使用分布对象模拟掷骰时，通常希望将两个分布（无论是相关的还是独立的）组合成它们的联合分布，然后在此基础上施加投影，以求出掷骰结果的总和、最大值、最小值等等。这种需求非常普遍，因此我想编写一个简短的辅助函数，将这两个操作合并在一起。这个函数很短，但出奇地强大：

清单13.5 将先验、似然和投影合并到一个函数中

```csharp
public static IDiscreteDistribution<C> JointProject<A, B, C>(
    this IDiscreteDistribution<A> prior,
    Func<A, IDiscreteDistribution<B>> likelihood,
    Func<A, B, C> projection) =>
    prior.ToJoint(likelihood)
        .Project(pair => projection(pair.Item1, pair.Item2));
```

有了这个辅助函数，我们的优势掷骰分布变得非常简洁：

```csharp
var advantage = d20.JointProject(_ => d20, Math.Max);
```

简洁固然很好，但这个辅助函数的真正威力将在下一章中展现，届时我们将了解到一个关于用泛型接口表示概率分布的惊人事实——这个事实已经在前文中埋下了大量伏笔。

## 小结

- 我们在看到额外证据之前的观点，例如随机一个人感冒的概率，称为先验概率。我们在系统中将它们表示为概率分布对象。
- 我们对条件概率的观点，例如一个人感冒或不感冒时打喷嚏的不同概率，表示为以条件为输入并返回一个分布的似然函数。
- 理想情况下，似然函数捕捉的是与先验无关的世界事实。感冒的人比不感冒的人打喷嚏更多这一事实，与当前世界上有多少人感冒无关。似然函数是现实世界统计模型的基本组成部分。
- 给定先验和似然函数，我们可以计算联合分布：每个可能的条件对的分布。
- 从联合分布出发，我们可以结合使用过滤和投影来计算后验似然函数。该函数接受对某个结果（例如打喷嚏）的观察，并返回对某个原因（例如感冒）的改进估计。
- 贝叶斯概率可能违反直觉，尤其是当似然函数代表一种罕见疾病的检测准确性时。如果假阳性比真阳性更可能发生，看似准确的检测可能会给出极具误导性的结果。
- 程序需要在充满不确定性的现实世界中做出行动决策。在软件中做出基于证据的决策时，请确保你应用的是贝叶斯逻辑。仅仅因为某个测量有 99.5% 的准确率，并不意味着对结果有 99.5% 的置信度！计算中必须包含先验。
